# 原生计时核心（开机即完整监控）实现方案

## 一、背景与目标

**问题**：应用需要在**手机开机/重启后立即完整监控**（累计亮屏计时 → 到点全屏干预），而不要求用户先手动打开应用。

**现状根因**：为避免"后台拉起进程时缓存 FlutterEngine 无视图可附着导致黑屏"（ZUXOS 真机已复现），Dart 入口已从 `Application.onCreate` 推迟到 `MainActivity` 窗口就绪后再执行（`ensureDartEntrypoint`）。因此开机广播/划卡闹钟在**无 Activity** 的后台拉起进程时，Dart isolate 不运行 → 状态机不 tick → 既不累计亮屏时长，也不触发休息干预。原生 `ScreenMonitorService` 虽能开机自启并采集亮灭屏广播，但只是把事件推给（尚不存在的）Dart。

**目标**：把**亮屏累计、阈值判定、到点干预**下沉到 Kotlin，原生在开机后（只要进程被拉起）即全权负责监控；Dart 仅在用户打开应用或被干预拉到前台时作为 UI 层**读取原生权威状态**并渲染，用户主动操作（手动休息、休息期答题豁免、改设置）通过通道回写原生。

**关键设计原则**：**单一权威时钟** —— 原生 `ScreenTimeCore` 始终是唯一权威计时源，Dart 退化为"每秒轮询原生快照并镜像"。彻底消除"双时钟所有权/交接竞态"。

## 二、现状分析（关键结论，均基于实际代码）

- 状态机计时本质（[screen_time_machine.dart](file:///home/robin/mygit/screen_time_manager/lib/state_machine/screen_time_machine.dart)）：亮屏期间 wall-clock delta 累加到 `sinceLastGrant` 与 `dailyUsage.accumulated`；`sinceLastGrant >= quizInterval` → `_enterRest`（`restEndsAt = now + restDuration`）；resting 到期 → 回 tracking、`sinceLastGrant = 0`，且 `!canExempt` 时 `exemptionsUsedToday = 0`；跨天重置 `dailyUsage`/阈值/豁免。
- 控制器（[screen_time_controller.dart](file:///home/robin/mygit/screen_time_manager/lib/ui/screen_time/screen_time_controller.dart)）：`Timer.periodic(1s)` 内 `_rolloverRestStatsIfNeeded() + machine.tick() + _flushDaySnapshot()`；阶段变化钩子 `_onMachinePhaseChange` 负责干预 request/dismiss、start/stopScreenPinning、会话落库、快照固化；`reportScreenOn` 转发 `machine.setScreenOn` + 屏幕会话落库；休息统计（`_todayRestCount/_todayRestElapsed/_todayRestExemptions`）为控制器内存态。
- 原生（[ScreenMonitorService.kt](file:///home/robin/mygit/screen_time_manager/android/app/src/main/kotlin/com/screen_time_manager/ScreenMonitorService.kt)）：前台服务内动态注册亮灭屏接收器 → `ScreenEventBus.emitScreenOn` → EventChannel；`start()` 已包 `runCatching`（后台 FGS 启动被拒不致命）。开机自启（[BootReceiver.kt](file:///home/robin/mygit/screen_time_manager/android/app/src/main/kotlin/com/screen_time_manager/BootReceiver.kt)）已实现，条件是 `monitor_bootstrap.user_started`。
- 干预路径已原生自足：[ScreenMonitorChannels.kt](file:///home/robin/mygit/screen_time_manager/android/app/src/main/kotlin/com/screen_time_manager/ScreenMonitorChannels.kt) 的 `requestIntervention`（`startActivity(MainActivity)` + 全屏 intent 通知 + `InterventionOverlay` 兜底）与 `startScreenPinning`（`RestGuard.arm()` + `startLockTask`）。
- 通道与接线：[platform_channels.dart](file:///home/robin/mygit/screen_time_manager/lib/platform_channel/platform_channels.dart) 定义 `MonitorChannel` / `InterventionBridge`；[platform_monitoring_native.dart](file:///home/robin/mygit/screen_time_manager/lib/platform_channel/platform_monitoring_native.dart) 仅 Android 返回真实通道（其余平台/测试环境为 null → 控制器退化 Timer 驱动）。
- 测试与桌面/Web 依赖"null 通道 → 本地 Timer 驱动"的退化路径（168 个测试）。
- Android 构建：[android/app/build.gradle.kts](file:///home/robin/mygit/screen_time_manager/android/app/build.gradle.kts) 无 `dependencies`/`testImplementation` 块，无 `src/test`。

                                     │                          │

## 四、改动清单

### A. Kotlin 原生（权威计时核心）

#### A1. 新增 `ScreenTimeCore.kt`（纯 Kotlin 逻辑，无 Android 依赖，可 JUnit 测试）

路径：`android/app/src/main/kotlin/com/screen_time_manager/ScreenTimeCore.kt`

**抽象外部依赖**（便于单测，构造注入）：
```kotlin
interface CoreClock {
    fun wallMs(): Long        // System.currentTimeMillis()
    fun realtimeMs(): Long    // SystemClock.elapsedRealtime()，进程死亡后仍连续
}
interface CoreStore {
    fun getLong(key: String, def: Long): Long
    fun getInt(key: String, def: Int): Int
    fun getString(key: String, def: String?): String?
    fun put(values: Map<String, Any>)   // 批量写入
}
enum class CoreEffect { NONE, ENTER_REST, EXIT_REST }
```

**持久化键**（`screen_time_core` prefs）：

| key | 类型 | 默认 | 说明 |
|---|---|---|---|
| `day` | String | 当前日 `yyyy-MM-dd` | 用于跨天重置 |
| `screen_time_sec` | Long | 0 | 今日累计亮屏（秒）|
| `threshold_sec` | Long | 0 | 自上次豁免通过/休息结束以来的进度 |
| `exemptions_used` | Int | 0 | 今日已用豁免（状态机口径）|
| `phase` | String | `tracking` | `tracking` / `resting` |
| `rest_ends_at_ms` | Long | 0 | 休息截止（wall ms，UTC）|
| `rest_start_ms` | Long | 0 | 当前休息起点（wall ms）|
| `rest_count` | Int | 0 | 今日触发休息次数（含进行中）|
| `rest_elapsed_sec` | Long | 0 | 今日**已完成**休息实际秒数（不含进行中）|
| `rest_exemptions` | Int | 0 | 今日休息期豁免次数 |
| `config_quiz_sec` | Long | 900 | 亮屏阈值（来自 Dart 推送）|
| `config_rest_sec` | Long | 600 | 强制休息时长 |
| `config_daily_limit` | Int | 2 | 每日豁免上限 |
| `is_screen_on` | Bool | false | 当前屏幕状态 |
| `last_update_realtime_ms` | Long | 0 | 上次累计时刻（elapsedRealtime，跨进程死亡有效）|

**状态机逻辑**（与 Dart `ScreenTimeMachine` 对齐）：

- `load()`：读回持久化；缺失则初始化 `day=今天`、phase=tracking、config 用默认。
- `setScreenState(isOn)`：先对**当前 interval 做一次收尾累计**（见下），再置 `is_screen_on`，`last_update_realtime_ms = realtimeMs()`。
- `tick(): CoreEffect`：
  1. `rolloverDayIfNeeded()`（按 `wallMs` 的当地日期；跨天则重置 `screen_time_sec/threshold_sec/exemptions_used/rest_count/rest_elapsed_sec/rest_exemptions`，`rest_start_ms/rest_ends_at_ms` 视 resting 情况处理，`day` 更新为今天）。
  2. 若 `phase == resting`：`wallMs >= rest_ends_at_ms` → 置 tracking、`threshold_sec=0`、`rest_elapsed_sec += (now - rest_start_ms)`；`rest_start_ms=0/rest_ends_at_ms=0`；若 `exemptions_used >= config_daily_limit` → `exemptions_used=0`；返回 `EXIT_REST`。否则返回 `NONE`。
  3. 若 `phase == tracking && is_screen_on`：`delta = max(0, realtimeMs() - last_update_realtime_ms)`（上限 clamp 到 `config_quiz_sec` 的若干倍以防异常；实现取 `min(delta, 3600_000)`）；`screen_time_sec += delta/1000`；`threshold_sec += delta/1000`；若 `threshold_sec >= config_quiz_sec` → 置 resting、`rest_ends_at_ms = wallMs + config_rest_sec*1000`、`rest_start_ms = wallMs`、`rest_count++`，返回 `ENTER_REST`。
  4. `last_update_realtime_ms = realtimeMs()`；节流持久化（≥5s 或发生转移时立即持久化）。
- `prepareForTakeover()`（服务 `onCreate` 调用）：`rolloverDayIfNeeded()` 后 `last_update_realtime_ms = realtimeMs()`，**不累计**进程死亡期间的间隔（避免把深度睡眠/重启期间误计；代价 ≤5s，与现有 day_snapshot 丢失窗口一致）。
- `configure(quizSec, restSec, dailyLimit)`：更新 config 字段并持久化。
- `manualRest(): CoreEffect`：仅 tracking 时置 resting（同上），返回 `ENTER_REST`。
- `consumeExemption(): CoreEffect`：仅 resting 且 `exemptions_used < config_daily_limit` 时，置 tracking、`exemptions_used++`、`rest_exemptions++`、`threshold_sec=0`、`rest_elapsed_sec += (now - rest_start_ms)`、清空 rest 起止，返回 `EXIT_REST`；否则 `NONE`。
- `snapshot(): CoreSnapshot`：返回当前全部字段（供通道）。

> 说明：`rest_elapsed_sec` 只累计**已完成**休息；进行中的部分以 `rest_start_ms`（配合 `now`）由 Dart 侧补算，保证与主页 `todayRestDuration` 语义一致。

#### A2. 新增 `TimeCoreHost.kt`（宿主：SharedPreferences 存储 + 系统时钟 + 效果执行 + 单例）

路径：`android/app/src/main/kotlin/com/screen_time_manager/TimeCoreHost.kt`

- `object TimeCoreHost`：
  - `fun core(context: Context): ScreenTimeCore`（惰性创建，Store 用 `getSharedPreferences("screen_time_core", MODE_PRIVATE)`，Clock 用系统实现）。
  - `fun applyEffect(effect: CoreEffect, context: Context)`：`ENTER_REST` → `ScreenMonitorChannels.requestIntervention(context, "resting")` + `ScreenMonitorChannels.startScreenPinningInternal()`；`EXIT_REST` → `ScreenMonitorChannels.dismissIntervention()` + `stopScreenPinningInternal()`；`NONE` 忽略。
- 该 Host 使 **服务（驱动 tick）与通道（读取/变更）共用同一 core 实例**，且通道在服务未运行时也能读写持久化值。

#### A3. 修改 `ScreenMonitorChannels.kt`

- 新增 `registerCore(engine, context)` 与在 `register()` 中调用：MethodChannel `<ns>/core`：
  - `snapshot` → `result.success(TimeCoreHost.core(ctx).snapshot().toMap())`
  - `configure`（args: `quizSeconds`/`restSeconds`/`dailyLimit`）→ `core.configure(...)`；`result.success(null)`
  - `manualRest` → `applyEffect(core.manualRest(), ctx)`；`result.success(null)`

#### A4. 修改 `ScreenMonitorService.kt`

- `onCreate`：`TimeCoreHost.core(this).prepareForTakeover()`；启动 `Handler(Looper.getMainLooper())` 每秒 `postDelayed` 的 tick 循环：
  ```kotlin
  private val coreTicker = object : Runnable {
      override fun run() {
          val effect = TimeCoreHost.core(this@ScreenMonitorService).tick()
          if (effect != CoreEffect.NONE) TimeCoreHost.applyEffect(effect, this@ScreenMonitorService)
          mainHandler.postDelayed(this, 1000L)
      }
  }
  ```

#### B8. 修改 `screen_time_machine.dart`（新增快照镜像方法）

新增方法（`restoreDay` 保留给旧 DB 路径）：
```dart
/// 用原生权威快照镜像状态（不本地累计）。字段无变化时不 notify。
void applyNativeSnapshot({
  required Duration usedToday,
  required Duration thresholdProgress,
  required int exemptionsUsedToday,
  required bool isScreenOn,
  required bool resting,
  DateTime? restEndsAt,
}) {
  final now = _clock();
  var state = ScreenTimeState.initial(
    now: now, quizInterval: _settings.quizInterval, isScreenOn: isScreenOn,
  ).copyWith(
    dailyUsage: DailyUsage.today(now).addScreenTime(usedToday),
    sinceLastGrant: thresholdProgress,
    exemptionsUsedToday: exemptionsUsedToday,
  );
  if (resting && restEndsAt != null && restEndsAt.isAfter(now)) {
    state = state.copyWith(phase: AppPhase.resting, restEndsAt: restEndsAt);
  }
  if (state == _state) return;
  _state = state;
  _lastTickAt = now;
  notifyListeners();
}
```

#### B9. 修改 `screen_time_controller.dart`

- 构造新增可选参数 `TimeCore? timeCore`（默认 null → 全旧行为，桌面/Web/测试不变）。
- `Timer.periodic(1s)` 回调改为分支（加 `_syncing` 重入保护）：
  ```dart
  final core = timeCore;
  if (core == null) {
    _rolloverRestStatsIfNeeded(); machine.tick(); _flushDaySnapshot();
  } else if (!_syncing) {
    _syncing = true;
    try {
      final s = await core.snapshot();
      machine.applyNativeSnapshot(
        usedToday: s.usedToday, thresholdProgress: s.thresholdProgress,
        exemptionsUsedToday: s.exemptionsUsedToday, isScreenOn: s.isScreenOn,
        resting: s.resting, restEndsAt: s.restEndsAt);
      // 镜像原生休息统计（原生为权威）
      _todayRestCount = s.restCount;
      _todayRestExemptions = s.restExemptions;
      _todayRestElapsed = s.restCompleted;
      if (s.resting) { _restStart = s.restStart; _restPlanned = machine.settings.restDuration; }
      else { _restStart = null; _restPlanned = null; }
    } catch (_) { /* 通道异常：跳过本次 */ }
    finally { _syncing = false; }
  }
  ```
- `restoreFromSnapshot()`：`timeCore != null` 时改为 —— 先 `snapshot()`；
  - 若 `!hasDayData` 且本地 DB 有当日快照 → `await core.seedFromSnapshot(DB 值)` 后重新 `snapshot()`（**升级迁移**，避免首次切原生模式时当日数据归零）；
  - 再 `machine.applyNativeSnapshot(...)` 并镜像统计；跳过 DB 路径。
  - `timeCore == null` 时保持原有 DB 恢复逻辑不变。
- 用户操作转发（`timeCore != null` 时，失败则 `catch` 后回退本地方法）：
  - `manualRest()` → `await timeCore.manualRest()`（回退 `machine.restNow()`）。
  - 休息期答对（`submitRestAnswer` 的 correct 分支）→ `machine.endRestEarly()` 改为 `await timeCore.consumeExemption()`（回退 `machine.endRestEarly()`）；`_todayRestExemptions++` **不再本地自增**（原生权威，下一轮快照覆盖）；`_todayRestCount`/`_todayRestElapsed` 同理由快照覆盖；仍保留 `_restEndedEarly = true` 与 `_recordSnooze(...)` 落库。
  - `updateTiming(...)` → 追加 `unawaited(timeCore.configure(machine.settings))`。
- 原生模式下的**抑制**（均以 `if (timeCore == null)` 包裹原逻辑）：
  - `_onMachinePhaseChange` 中的**干预 request / dismiss / startScreenPinning / stopScreenPinning** 不执行（由原生 `TimeCoreHost.applyEffect` 负责）；
  - 进入/离开 resting 的 `_todayRestCount++`、`_todayRestElapsed += actual`、`_rolloverRestStatsIfNeeded` 不执行（原生权威，由轮询覆盖）；但**保留** `_flushRestSession` 落库 rest_session（用 `_restStart/_restPlanned`），及 `_flushScreenSession` 落库 screen_session；
  - `reportScreenOn`：不调用 `machine.setScreenOn`（原生权威，快照镜像），仅做屏幕会话边界记录（亮屏开新会话、灭屏落库）；
  - `_flushDaySnapshot` 在原生模式下直接 return（原生已持久化）；`dispose` 中的行为保持。

## 五、关键决策与取舍

1. **单一权威时钟在原生**：彻底避免双时钟交接竞态；Dart 每秒轮询（轮询频率 = 原 tick 频率，无新增 UI 重建，`applyNativeSnapshot` 仅在字段变化时 notify）。
2. **桌面/Web/测试零回归**：`timeCore == null` 时控制器完全走原有本地路径；现有 168 测试不受影响。
3. **跨进程/重启的正确性**：用 `elapsedRealtime` 差值累计，进程死亡 1~5s 由重启闹钟快速恢复；服务 `onCreate` 采用 `prepareForTakeover`（不累计死亡间隔）避免把深度睡眠/重启期间误计，丢失窗口 ≤5s（与原 day_snapshot 一致）。
4. **升级迁移**：首次进入原生模式且原生无当日数据时，用 `seedFromSnapshot` 把 DB 当日快照灌入原生，避免当日数据归零。
5. **已知边界（不新增解决）**：完全在后台（Dart 未运行）期间发生的休息/亮屏会话**不会写入 `rest_session`/`screen_session` 明细表**（SQLite 由 Dart 侧的 sqflite 管理）；聚合统计（`day_snapshot` 语义的当日累计、休息统计）由原生 core 完整保留，主页展示不受影响。如后续需要明细，另立任务（原生侧缓冲 + Dart 启动时落库）。
6. **不修改 pubspec 锁定依赖**；不改变现有 Notification / 双闹钟 / 音量紧急退出逻辑。
